# context7 導入調査

## 調査日

2026-08-14

## 目的

Codex / Claude Codeで外部library、framework、SDK、API、CLI、cloud serviceの現行documentationを取得し、古い学習情報による誤実装を減らせるか確認する。

## 公式情報から確認したこと

### Client導入

- Codexは公式plugin marketplaceからcontext7 pluginを追加できる。
- Codexは`codex mcp add context7 -- npx -y @upstash/context7-mcp`によるMCP直接登録もできる。
- Claude Codeは`claude mcp add --scope user context7 -- npx -y @upstash/context7-mcp`でuser scopeへ登録できる。
- local stdioだけでなくremote HTTP transportも提供されるが、AFではclient差を小さくするためlocal stdioを共通fallbackとする。

### 認証

- MCP serverは`--api-key`と`CONTEXT7_API_KEY`を受け付け、両方ある場合はCLI optionが優先される。
- AFはsecret値をcommand例、repository、template、manifest、logへ保存しない。user環境の`CONTEXT7_API_KEY`を利用する。

### Tool contract

- library名と質問から`resolve-library-id`でContext7互換IDを解決する。
- 解決済みIDを使い`query-docs`でdocumentationを取得する。
- `get-library-docs`はv2.0.0で削除され、`query-docs`へ置き換えられた。
- queryは単一conceptに絞る。複数の独立した論点を1回へまとめると検索品質が薄まるため分割する。

### Routing境界

Context7公式ruleはlibrary/framework/SDK/API/CLI/cloud serviceのcode generation、setup、configuration、documentation取得を対象とする。一般的なrefactor、business logicのdebug、code review、一般概念には使わない。質問内容は外部serviceへ送られるため、secret、個人情報、production data、非公開sourceをqueryへ含めない。

## 結論

AFへ採用する。全作業をblockするmustではなくrecommended toolとし、対象taskではWeb検索より先に利用する。未接続時は公式Web documentationへ縮退し、導入手順を`docs/framework/context7.md`から辿れるようにする。
