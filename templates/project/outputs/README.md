# outputs — 配布する成果物

原稿から生成した配布物（HTML、PDF、スライド、レポート等）を置く。**原稿ではない。**

## 原則

- **原稿の正本は `docs/knowledge/` 側**。ここにあるのは生成物。
- 生成物を直接編集しない。原稿を更新してから再生成する。
- 生成元の原稿へのリンクを、生成物か原稿のどちらかに必ず残す。

| | 場所 | 編集する |
|---|---|---|
| 原稿 | `docs/knowledge/materials/<topic>.md` | ○ |
| 生成物 | `outputs/<topic>.<ext>` | ×（再生成する） |

## コミットする / しない

**原則コミットする。** 対外資料は事業の成果物そのもので、非エンジニアが参照する最終形でもある。repository 内の成果物だけで再現するという原則を保つため、配布物は repository に置く。

除外するのは受け手のいないものだけ:

- `outputs/tmp/` — 使い捨ての検証用レンダリング。`.gitignore` 済み。

## バイナリの扱い

git の履歴は追記型で、**一度入れたバイナリは消えない**。pptx / pdf / 画像を頻繁に更新すると clone が重くなり続ける。

- テキスト形式（HTML / SVG / Markdown）は差分圧縮が効くのでそのままコミットしてよい。
- バイナリは、小さく更新頻度が低いものに限る。
- 大きい、または頻繁に更新するバイナリは Git LFS を使うか、外部ストレージに置いて**リンクだけ**を原稿に残す。
- 迷ったら、まず HTML など**テキスト形式で出せないか**を検討する。

## 秘密情報

生成物にも secret、個人情報、未公開の価格・顧客名が混入しうる。**対外配布物ほど確認する。** 判断に迷うものは Human Approver に渡す。
